## Why tag rules?

Some guidelines (response tone, length, completion behavior) are optimized
for a specific model. When the model changes, these rules can become
obsolete or counterproductive. Tagging makes them findable in a single
command.

______________________________________________________________________

## Tag format

```text
@[MODEL_NAME]
```

- `MODEL_NAME`: model identifier, lowercase, dashes allowed.
- Placed as an HTML comment (`<!-- @[...] -->`) or inline within a rule block.
- A rule can have **multiple tags** (e.g. `@[<model-id>] @[claude-opus-4]`).

### Valid examples

```markdown
<!-- @[<model-id>] Short responses by default on this model -->

<!-- @[claude-haiku-4-5] This rule compensates for a lower-effort model's tendency to skip steps -->

<!-- @[claude-haiku-3] Reduced injection context to limit tokens -->
```

## Automatic inventory

```bash
# See all tagged rules (all models)
node .claude/hooks/model-debt-inventory.cjs

# Filter on the current model (defined in hooks-config.json)
node .claude/hooks/model-debt-inventory.cjs --current

# Filter on a specific model
node .claude/hooks/model-debt-inventory.cjs --model=<model-id>

# JSON output for CI integration
node .claude/hooks/model-debt-inventory.cjs --format=json
```

## Procedure when changing model

1. Run `node .claude/hooks/model-debt-inventory.cjs --format=json`
   to list the rules to review.
1. For each rule tagged with the old model:
   - Check whether it remains valid with the new model.
   - Update: replace the tag or remove the rule.
1. Update `modelDebt.currentModel` in `hooks-config.json`.
1. Push the changes.
