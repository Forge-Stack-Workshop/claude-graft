# Django Migrations Review

Review a Django migration for safety, performance, and zero-downtime deployment.
Usable as a Claude Code slash command: `/migration-review <path>`

______________________________________________________________________

## Instructions for Claude Code

Run during PR review of migration files, before merging to develop/main. Related files: `.claude/rules/django-migrations-review.md`, `.claude/rules/secrets-config.md`.

**Key Principle**: A slow migration in prod = worse than no migration. Test on production-like data.

Ensure migrations meet Padam-AV's strict requirements for zero-downtime deployments:

1. **Backwards Compatible**: Old and new code coexist during rolling updates
1. **Sub-10-Second**: Migrations complete on largest prod DB in \<10 seconds
1. **Reversible**: All migrations can be rolled back (no data loss)
1. **Idempotent**: Running twice = running once (no side effects)
1. **Auditable**: Clear comments explaining why changes are safe

## Migration Compliance Checklist

```
✅ Auto-generated by Django (no manual edits)
✅ Atomic operations (all-or-nothing)
✅ Reversible (RunPython has reverse function)
✅ < 10 second execution on largest prod table
✅ Backwards compatible (old code + new code coexist)
✅ Idempotent (running twice = running once)
✅ English-only comments explaining *why* not just *what*
✅ No business logic in migrations
✅ No hardcoded secrets (use env vars)
✅ Tested locally and on staging DB
```

______________________________________________________________________

## Common Patterns for Safety

**Adding Non-Nullable Fields** (3-step process):

1. Add field as nullable + backfill with default
1. Deploy code that uses new field
1. Set field to NOT NULL

**Deleting Fields** (3-step process):

1. Remove from code, mark as deprecated in migration
1. Deploy 1+ releases with deprecation warning
1. Delete column in migration

**Index Operations**:

- Use `CONCURRENTLY` for PostgreSQL (non-blocking)
- Never create index on table with millions of rows inline

______________________________________________________________________

## Expected Output

After reviewing a migration, confirm:

- ✅ Passes `make tests` (django-migration-linter validation)
- ✅ Execution time < 10 seconds on staging DB
- ✅ Rollback verified (tested `manage.py migrate {app} zero`)
- ✅ No secrets leaked (scan via `make ruff-check`)
- ✅ Clear comments explaining backwards compatibility approach
- ✅ Ready for code review and merge
