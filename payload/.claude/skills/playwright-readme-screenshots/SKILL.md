# Playwright README screenshots

Docs screenshots are generated by the test suite, not pasted by hand. They are
captured against the production bundle, deterministically, on every full E2E run —
so a screenshot in the README always shows the UI that actually ships.

## The pattern

1. A dedicated spec (`tests/e2e/screenshots.spec.ts`) navigates to each documented
   surface and calls `page.screenshot()` into `docs/screenshots/<name>.png`.
2. It runs against the **production** build (the same bundle you deploy), not the
   dev server, so styling and content match release.
3. Determinism: fixed viewport, seeded/fixture data, disabled animations, waited
   network-idle. Same input → byte-stable image (or tolerance-bounded diff).
4. It runs as part of the full E2E job; a docs image is never updated manually.

## Why

Multiple projects independently re-author the identical convention, with the same
file path and wording. Making it a skill removes the re-invention and guarantees
docs images track the shipped UI instead of rotting.

## Checklist

- [ ] `screenshots.spec.ts` captures every README/docs surface.
- [ ] It targets the production bundle, not the dev server.
- [ ] Viewport, data, and animations are pinned for determinism.
- [ ] Images land in `docs/screenshots/` and are refreshed only by the E2E run.
- [ ] The README references those paths, never hand-pasted images.
